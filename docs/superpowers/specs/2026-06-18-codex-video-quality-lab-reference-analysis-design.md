# Codex Video Quality Lab Reference Analysis Design

## 背景

当前 `video_factory_project` 已经具备单条视频生成的雏形：脚本、分镜、TTS、字幕、素材拼接和渲染。但近期样片暴露出一个更本质的问题：系统能产出视频，却不能稳定产出“像高质量真人内容”的视频。

失败样片的问题不是某个遮罩、字幕或素材可以单点修好，而是缺少一套先定义质量、再生产视频、再验证差距的流程。因此第一阶段目标从“制作某一类视频”调整为“建立视频质量拆解能力”。

## 目标

第一阶段建设 **Codex Video Quality Lab：参考视频质量拆解器**。

输入一条本地高质量参考视频，输出三类结果：

- `quality_report.md`：给人看的质量拆解报告，解释参考视频为什么高级、为什么不像 AI、哪些地方不可盲目复刻。
- `production_template.md`：给后续视频制作使用的模板草案，沉淀脚本、素材、字幕、声音、剪辑规则。
- `scorecard.md`：给后续样片质检使用的评分标准草案，指出新视频与参考视频的差距。

第一版的验证样本为 `/Users/king/Downloads/下载.mp4`。

## 非目标

第一版不做批量视频生成，不接入抖音网页，不自动下载平台视频，不做账号数据抓取，不做发布级版权判断，也不承诺完全自动识别所有剪辑语义。

抖音链接、截图描述、批量任务、自动评分、自动返工都作为后续阶段能力。第一版优先把本地视频拆解报告做扎实。

## 已确认方向

第一阶段不固定足球、教程、带货或热点赛道。系统要解决的是通用视频质量问题。

第一版输入范围采用长期与短期分层：

- 长期支持：本地视频文件、抖音公开视频链接、视频截图加人工描述。
- 第一版落地：本地视频文件。

第一版输出范围采用递进方式：

- 先输出完整拆解报告。
- 再从报告提炼制作模板。
- 再从模板提炼评分标准。

方案顺序采用：专家拆解报告优先，再做模板提取，再做评分标准。自动指标分析放到后续增强，不作为第一版核心。

## 报告结构

每条参考视频输出一份结构化拆解报告，包含以下 8 个部分。

### 1. 基础信息

记录时长、分辨率、画幅比例、帧率、音频信息、横竖屏、主要内容类型和视频整体形态。

### 2. 时间线拆解

按 3 到 10 秒粒度拆分视频，标注每段功能，例如开头钩子、观点提出、证据展示、转折、演示、结论、互动引导。

### 3. 镜头与画面系统

描述真人出镜比例、B-roll 比例、屏幕录制比例、图表比例、字幕覆盖区域、主视觉是否统一、画面是否服务口播。

### 4. 字幕系统

分析字体大小、位置、颜色、双语结构、逐句出现方式、重点词高亮方式、旧字幕或 UI 是否冲突。

### 5. 声音与口播

分析语速、停顿、情绪、句子长度、口语化程度、是否像真人表达、背景音乐和音效是否增强节奏。

### 6. 剪辑节奏

分析镜头切换频率、画面变化点、字幕变化点、信息密度、拖沓区和节奏峰值。

### 7. 真实感来源

指出视频为什么不像 AI，例如真人动作与内容同步、素材可信、语言自然、界面系统统一、信息具体、保留了真实内容的不完美细节。

### 8. 可复刻规则

总结成可执行生产规则，覆盖脚本、素材、字幕、声音、剪辑、包装和质检。

## 系统模块

第一版以本地命令行工具为主，不先做复杂网页后台。

### Video Ingest

读取本地视频，验证路径存在，提取媒体信息，并建立本次分析输出目录。

### Frame Sampler

按固定间隔和关键时间点抽帧，生成 `contact_sheet.jpg` 和 `sample_frames/`，用于快速观察完整视频结构。

### Timeline Analyzer

基于抽帧、音频时长和人工判断生成初版时间线。第一版允许由 Codex 结合抽帧进行专家式判断，不追求完全自动识别所有镜头边界。

### Quality Analyst

输出参考视频的质量拆解，重点回答：高级感来自哪里、AI 味风险在哪里、哪些规则可以复刻、哪些地方不能盲目复制。

### Template Extractor

从拆解报告提炼制作模板，覆盖开头结构、叙事结构、素材规则、字幕规则、声音规则、剪辑节奏和画面包装规则。

### Scorecard Builder

从报告和模板生成评分标准，用于以后评估新样片。评分维度包括画面匹配度、素材可信度、口播自然度、字幕干净度、节奏密度、语义一致性和整体真实感。

## 数据流

本地视频文件进入系统后，经过以下流程：

`本地视频` → `媒体分析` → `抽帧/采样` → `时间线拆解` → `质量报告` → `制作模板草案` → `评分标准草案`

输出目录结构：

```text
video_factory/output/analysis/<video_slug>/
  media_info.json
  contact_sheet.jpg
  sample_frames/
  timeline.md
  quality_report.md
  production_template.md
  scorecard.md
```

## 第一版验证方式

使用 `/Users/king/Downloads/下载.mp4` 做第一条验证样本。

输出必须能回答以下问题：

- 原视频的高级感来自哪里。
- 之前失败样片为什么 AI 味重。
- 如果要复刻参考质量，脚本、素材、字幕、声音和剪辑必须遵守哪些规则。
- 下一条样片开工前必须检查哪些条件。

第一版验收标准：

- 报告能解释“为什么好”，不能只写“高级、节奏快”这类空泛描述。
- 模板能指导下一条视频如何制作。
- 评分标准能指出新视频具体哪一层不合格。
- 报告至少能解释当前失败版 80% 以上的问题。

## 关键质量原则

视频质量来自整体一致性，而不是单点特效。

对于参考视频拆解，必须特别关注以下原则：

- 内容语义和画面必须一致，不能把一个话题的母片硬改成另一个话题。
- 不能在已有完整 UI 系统上再叠一套新模板。
- 口播必须像真人表达，有取舍、停顿、重点和情绪。
- 字幕必须干净、可读、与原画面不冲突。
- 素材必须服务口播，而不是只填满时间线。
- 每条视频都需要质检环节，不合格应返工，而不是直接发布。

## 后续阶段

第一阶段完成后，再进入以下方向：

- 将拆解模板用于生成一条新的高质量样片。
- 增加自动指标分析，例如镜头切换频率、字幕占比、音频节奏、画面亮度和重复画面。
- 支持抖音公开视频链接或用户提供的网页截图。
- 建立多参考视频的风格库和模板库。
- 建立批量任务队列、质量评分、自动返工和人工审批流程。

## 风险与约束

完全自动判断“高级感”在第一版不现实，因此第一版采用工具辅助加 Codex 专家拆解的方式。

平台视频和赛事素材涉及版权与平台规则。第一版只分析用户提供的本地视频，不自动抓取平台内容，也不把内部研究样片等同于可发布成片。

当前工作目录不是 git 仓库，设计文档可以写入本地文件，但不能完成 git commit。
