King-AI-video · 批量视频生产系统

一条视频，是怎么被自动造出来的

给系统一份原始视频文案（或一段素材），它自己完成改写口播 → 合成配音 → 对齐时间轴 → 配图 → 拼装 → 加特效 → 烧字幕七步，最后吐出一条可直接发布的成片。全程无人值守，一张任务清单进、N 条成片出。

一句话流程（最简三行版）

1把原文改写成原创口播稿，再配上人声，并用 AI 听写出每句话的精确起止时间。
2按这份时间表，给每个画面镜头配一张图（先翻自家图库，翻不到才现生），然后拼成带运镜和转场的视频。
3最后叠上开屏钩子、金句、关键词、数字等花字特效，再烧上字幕，成片 release_subtitled.mp4 完工。
★

核心架构：一条「主时间轴」当全片唯一时钟

这是整个系统能跑通、图片和声音能严丝合缝对上的地基。老板只需记住这一件事，其余都是它的延伸。

为什么图片、字幕、特效都能对准声音

配音一定稿，系统立刻用 AI 把口播「听写」成逐句真实起止时间表，写进 timeline.json。此后全链所有环节都读这同一份时间表。

过去的病根：听写对齐原本发生在最后一步（字幕阶段），特效只能靠「这句占全文多少字」去估算该出现在第几秒 —— 结果字幕能对上音频，特效却对不上，数字弹早了、金句弹晚了。

现在的解法：把「配音」从拼装里拆出来提前到改写之后单独成一步，配音一落定就立刻听写对齐、产出 timeline.json（代码见 voice.py → timeline.py）。生图、拼装、特效、字幕四个环节全都消费它 —— 全链只有一个时钟，自然全都对齐同一条声音。

  • timeline.json 产出
    配音阶段用 whisper 听写对齐，逐句得到 { 文本, start, end }，对齐的正是最终混进成片的那条音轨。
  • ↳ 喂给 · 配图
    按「句子在哪停顿」把画面切成变长拍（卡话切）—— 镜头切换点落在语音停顿处，而不是机械每 5 秒切一次。
  • ↳ 喂给 · 拼装
    拼装侧用同一个函数、同一份输入算拍，所以「第几张图、放多久」和配图侧算的分毫不差。
  • ↳ 喂给 · 特效
    金句、数字、关键词直接落在含它那句话的真实起点上，不再靠字数估算。
  • ↳ 喂给 · 字幕
    字幕直接用这份时间表逐句烧录，跳过重复听写（省一次 ASR）。

✕ 没有主时间轴

特效靠「字数占比」估算落点 → 5000 这个数字弹在了错误的位置，金句和口播错开，观感散。

✓ 有主时间轴

所有画面/文字都锚定同一条声音的真实秒数 → 所见即所听，图片跟着话走，字幕跟着话走。

改写口播稿 rewrite

代码：rewrite.py
AI · LLM
输入

原始视频文案 / 字幕 / 转写文本（视频、音频会先走 ASR 转写）；可选创作 brief 与文风。

干了什么
  • 让大模型原创重写：换钩子、换叙事顺序、只保留真信息，不照抄原句。
  • 按目标时长换算字数预算（4.8 字/秒，实测校准）。
  • 为每节标 emphasis 强调计划：keyword / number / golden 三类，全片至少 1 条金句。
  • 字数闭环：估算时长不足目标 85% 就让 LLM 扩写重来，最多 2 轮（宁短勿废）。

04

拼装成片 assemble

代码：assemble.py
FFmpeg · 无 AI
输入

gen_assets 的图（或视频素材）＋ 配音 ＋ timeline.json ＋ 画幅/填充/时长。

干了什么
  • 第 k 拍用第 k 张图，拍时长＝该句群真实秒数，再按真实节归组。
  • 每张静图加 Ken Burns 运镜（8 款推拉摇移，确定性挑选、先超采样减抖）。
  • 节边界必转、长节内约每 15 秒转一次的 xfade 转场（0.4 秒，含时长补偿守恒）。
  • 混入配音（可选 BGM ducking），faststart 让浏览器能边下边播。

2

配图检索子流程：图库优先，省钱又保画风

核心原则：能翻自家图库就绝不花钱现生。每现生一张图都会自动入库，下一条视频就可能白嫖到它 —— 图库越用越肥，生图成本越用越低。代码见 image_gen.py。

先决定「要切几个镜头、每个镜头讲哪句话」——变长拍（卡话切）

系统读主时间轴，把口播按句子的真实停顿打包成一段段「拍」：累计到下限就封一拍，太长的单句拆成等份。这样画面切换点永远踩在语音的自然停顿处，而不是机械地每 5 秒硬切一次。

关键：配图侧和拼装侧调的是同一个权威函数、喂同一份输入，所以「算出来要几张图」和「拼装时要放几张图」天生一致，永不错位。（无主时间轴时才回落到旧的 5 秒均分。）

一拍时长 2.5 ~ 8 秒 一拍 = 一张图 单 job 现生上限 60 张（复用不计）
🎬STEP 1

LLM 派生每拍需求

大模型为每一拍写出画面提示词 + 视觉类目 + 检索标签（人物 / 场景 / 物品 / 数据图表 / 抽象概念 / 情绪氛围）。

⚡STEP 2

本地二级粗排

纯本地毫秒级打分选出候选：条目标签命中拍文案 +3／个，提示词与拍文案二元组重合 +1／个。每拍取前 20，全片截到 150 张喂给下一步。

🎯STEP 3

LLM 精选（库优先）

大模型看着候选库图为每拍拍板：reuse（复用某张库图）或 generate（给新生成提示词）。同一张库图最多用一次，代码端再去重兜底。

命中复用 ¥0
🖼STEP 4

现生 + 入库

翻不到的才调豆包 Seedream 4.0 现生（统一美式漫画画风、钉死不出文字），落到本拍的 img_NN。

新生成 ¥0.2 / 张
❄️

滚雪球：生成的图立刻回写图库

每张新生成的图都会写进图库并登记索引（素材库/图片/<类目>/，同内容不重复落盘）。库越大，下次 LLM 精选时命中率越高、要花钱现生的越少 —— 这是「生成入库、下次复用省钱」的既定原则。入库失败只告警，不影响本条成片。

3

特效类型清单：四种花字，各司其职

章节卡 / 序号卡已彻底退役，节奏改由下面四类「跟着声音走」的花字承担。全部落点优先用主时间轴的真实句起点。代码见 effects.py。

特效类型是什么何时触发样式 / 音效
hook_opener开屏钩子 开头的透明大字叠层，把 hook 按子句切成 2~3 行，随口播逐条弹入 —— 所见即所听，替代已退役的冷开场黑卡。 视频最开头（start = 0）。时长取 min(5 秒, 首节 ×0.9)，避免盖过正片开头。 大字逐行弹出，落点用真实句起止。音效：首行 whoosh 起势，后续行 swoosh。
golden_lines金句开屏 把 kind=golden 的金句做成三行式开屏卡（复用 hook 组件渲染），是全片的记忆点。 命中含该金句那句话的真实起点。相邻金句至少隔 20 秒，撞开屏/固定窗口就顺延，仍撞则丢弃（宁缺勿滥）。 三行大字。时长 = 该句时长 + 1.2 秒尾留白，封顶 4.5s（保证读得完）。
keyword_pop关键词弹出 把 keyword 类强调词弹到屏上（无 emphasis 时回落规则抽取：引号内词 > 数字短语 > 节标题头几字）。 emphasis 优先用真实句起点。做密度控制：相邻<8 秒抽稀、>20 秒真空补填；避开金句卡窗口 ±1 秒。 时长 1.6s。三色轮换：红 黄 白。
number_pop数字强调 把口播里的关键数字（如 3 倍 / 5 步 / 5000 条 / 30%）单独弹大，强化冲击力。 每节首个关键数字，全片最多 2 个。落点用含该数字那句话的真实起点（无时间轴时节起点后约 1 秒）。已弹的数字不再作关键词弹。 时长 1.4s，数字放大呈现。

音效怎么加：特效音默认开启（可关）。渲染时按每条特效的类型取对应音效文件，用 adelay 平移到该特效的落点混进音轨，amix 保住人声不被压过；默认音量 0.35。音效文件缺失只跳过、绝不阻断成片。

4

降级兜底：AI 环节坏了，也照样出片

系统的设计信条：每一个「增强型」AI 环节失败都自动回落到更简单的路径，而不是让整条视频崩掉。

增强件失败 → 自动降级，成片继续

下面这些环节即使 AI 出错、没凭据、网络抖动，系统也会走一条更朴素的备用路，你依然拿得到成片：

改写
扩写没把字数补够 → 止损保留现有稿，剩余缺口交给配音的变速微调（宁短勿废）。
主时间轴
听写对齐失败 → 只告警不阻断，下游生图/特效/字幕各自回落到「字数估算 / 自跑一次 ASR」。
配图
无凭据或解析失败 → 回落每节一张的节级配图；单拍生成失败跳过、超上限尾部循环、入库失败仅告警。
拼装
xfade 转场失败 → 回退全量硬切；变速探测失败 → 放行原音频。都不阻断。
特效
无主时间轴 → 落点用字符占比估算；片段分辨率不匹配跳过留痕；音效缺失跳过；翻译失败降纯中文。
字幕
主时间轴 → ASR 对齐 → 字符占比分摊，三级逐级降级；英文翻译失败退回纯中文。
⚠️ 唯二的硬门槛：「配音合成」（成片刚需）和「至少产出文案 / 至少产出一张配图」失败会让该 job 记为 failed 并停止 —— 但即便如此，其它 job 照常继续，整批不中断，最终成片逐级回落：字幕版 > 特效版 > 原拼装版。
